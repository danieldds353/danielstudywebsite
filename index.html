Written-answer practice

Try answering aloud or on paper before opening the checkpoints. These are fresh scenarios using lecture concepts, not assignment submission answers.

1. Explain structured design for four LANs in a single building. Distinguish its organizational benefit from the technical goals.

Checkpoints: access connects endpoints; distribution interconnects LANs; the lecture's campus core is unnecessary for this scope. Modularity and a clear hierarchy organize design and maintenance. Performance, availability and scalability require specific capacity, redundancy and expansion decisions.

Lecture 1, slides 28–33 and 43.

2. Compare client-based and client-server TPS designs. Explain why the location of data access logic matters.

Checkpoints: client-based keeps storage at the server but queries and application processing at the client, producing excessive data movement. Client-server performs data access at the server and can return the needed subset. Presentation stays at the client; application logic can be split. Justify performance and capacity separately from failure tolerance.

Lecture 2, slides 9–12.

3. A company needs short desktop connections and a long link through electrical interference. Recommend media for each and justify the trade-offs.

Checkpoints: twisted-pair is inexpensive and appropriate for typical desktop channels up to 100 m. Fiber with suitable optics supports the longer span and resists electromagnetic interference, at greater cost. Check distance, compatible connectors/optics, data-rate support and installation needs.

Lecture 3, slides 10–18.

4. Explain what CRC-32 does and what it cannot do. Relate your answer to TCP and UDP.

Checkpoints: the Ethernet receiver checks an error-detection value; corrupted frames are discarded. CRC does not repair damaged data. Reliable TCP delivery can recover via retransmission, whereas UDP itself provides no delivery/retransmission guarantee. Detection is not proof that absolutely no errors can ever go undetected.

Lecture 3, slide 32; Lecture 4, slide 9.

5. A Class B network needs at least 70 equal-size subnets. Derive the borrowed bits, mask, usable hosts and spare subnets.

Checkpoints: 2^6 = 64 is too small; borrow 7. Prefix /16 + 7 = /23; mask 255.255.254.0. Nine host bits remain: 2^9 − 2 = 510 usable hosts per subnet. There are 128 subnets, so 58 remain after allocating 70. More hosts than this per subnet require a different allocation or another subnet.

Lecture 4, slides 17–21. New subnetting scenario.

6. Explain why a /29 subnet has six usable host addresses, and why a Class B block and Class C block yield different subnet counts with that mask.

Checkpoints: 32 − 29 = 3 host bits, giving 8 total addresses minus network and broadcast = 6. Class B /16 borrows 13 bits, yielding 8,192 subnets; Class C /24 borrows 5, yielding 32. Final mask determines host count; original block determines how many subnets fit inside it.

Lecture 4, slides 19–21.

7. An update carries 300 useful bytes with 20-byte TCP, 20-byte IPv4 and 40-byte link overhead. Calculate efficiency, then explain the effects of doubling frequency and reducing payload to 30 bytes.

Checkpoints: total overhead 80; efficiency 300 / 380 = 78.95%. Doubling frequency leaves the ratio unchanged if every message keeps the same sizes. With 30 useful bytes, efficiency is 30 / 110 = 27.27%. More messages increase bytes per second; smaller payloads increase the overhead share. Use this question's stated overhead rather than memorizing a universal Ethernet value.

Lecture 3, slides 33–34. Fresh calculation using the efficiency method emphasized in Assignment 1.

8. Distinguish DNS, DHCP, ARP and routing when a host contacts a destination on another subnet.

Checkpoints: DNS resolves a hostname to an IP address if needed; DHCP can supply the host's IP configuration. The host sends remote-subnet traffic toward its gateway. ARP finds that gateway's local MAC address; routers use routing tables to forward the IP packet. ARP is not used by the sender to discover a remote host's MAC across the Internet.

Lecture 4, slides 10–14 and 22.
